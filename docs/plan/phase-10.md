## Conflicts and Risks

- Migration safety risk:
  - Adding `apartments.type` as required needs backfill for existing rows before strict `NOT NULL`.
- Data consistency risk:
  - Owner join must only use active owner rows (`owners.deleted_at IS NULL`, `users.deleted_at IS NULL`).
- Financial correctness risk:
  - Monthly totals and payment summary must remain derived from queries, never persisted as columns.
- UX interaction risk:
  - Row-click detail opening can conflict with edit/delete actions without event propagation handling.
- Type-shape drift risk:
  - Table, filters, stats, drawer, and export should share one normalized apartment row interface.
